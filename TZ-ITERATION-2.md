## 1. Счёт в пиках должен начинаться с «0», а не с «1»

**Что сейчас.** `js/main.js:230-242` — шаг степпера: `var next = (cur === null ? 0 : cur) + Number(btn.dataset.step)`. Из пустого поля `+` сразу даёт **1**. Кнопка `−` при этом заблокирована в пустом состоянии (`js/main.js:284`: `disabled = !editable || v === null || v === 0`), то есть «0» с клавиш степпера недостижим — его можно только вписать руками.

Итог: счёт **2–0** сейчас набирается за 4 тапа (`+ +` слева, `+` справа даёт 1, потом `−`).

**Что делаем.**

1. **Отсчёт начинается с нуля.** Из пустого состояния `+` ставит `0`, дальше `1, 2, 3 … 20`.
2. **`−` активна в пустом состоянии** и тоже ставит `0`. То есть один тап по любой из двух кнопок = `0`.
3. **`−` на нуле** возвращает поле в пустое состояние (плейсхолдер `-`). Если из полного счёта был выведен исход/BTTS (`syncScore`, `js/main.js:259-264`) — они сбрасываются вместе с ним.
4. **Автозаполнение второй стороны нулём.** Когда пользователь впервые задаёт значение на одной стороне (степпером или с клавиатуры), противоположное поле, если оно ещё пустое, становится `0`. Поле остаётся полностью редактируемым.

Новая стоимость в тапах: `0–0` — 1 тап, `2–0` — 3 тапа, `2–1` — 4 тапа. Было соответственно 2 / 4 / 3.

**Файлы.** `js/main.js` — обработчик `.stepper__btn` (230-242), `field.addEventListener('input')` (244-253), расчёт `disabled` в `renderCard()` (283-286). Бампнуть `?v=` для `js/main.js` в `index.html:1251` (сейчас без версии — добавить `?v=2`).

**Критерии приёмки.**
- Из пустой карточки один тап `+` показывает `0` с классом `has-value` (белый жирный, `css/main.css:522`).
- Счёт `2–0` набирается тремя тапами.
- `−` на нуле очищает поле, и карточка перестаёт считаться сделанным пиком, если исход/BTTS были выведены из счёта.
- Ручной ввод `0` с клавиатуры работает как раньше.

## 2. Лидерборд: топ-20 + позиция игрока с соседями

**Что сейчас.** `js/rankings.js:110-113` генерирует строки с 4 по 100 (97 строк подряд). Позиция игрока — 47 (`js/rankings.js:50`). Внизу висит фиксированная плашка `[data-rankings-pin]` (`index.html:1200-1205`), которая прячется, когда до строки игрока доскроллили (`js/rankings.js:135-152`).

**Что делаем.** Идея с соседями — хорошая, берём в работу целиком.

Структура списка сверху вниз:

1. **Подиум** — места 1–3 (без изменений, `index.html:396-419`).
2. **Список** — места 4–20. Всего на экране топ-20.
3. **Разделитель-разрыв** — новый элемент `.rankings-gap`: центрированное многоточие `⋯` цветом `rgba(255,255,255,.3)`, высота 32px. Визуально означает «здесь пропущены места».
4. **Блок «Your position»** — новый `.rankings-neighbours`:
   - подпись-заголовок `YOUR POSITION` в стиле `.arena-section-label`;
   - три строки `.rankings-row`: `N−1`, `N`, `N+1`. Своя строка — существующий модификатор `.rankings-row--you` (`css/rankings.css:331`) и `data-current-rank`;
   - под блоком строка-подсказка: `3 points to pass Noah Bennett (#46)` — разница очков до соседа сверху. Стиль: 12px, `--text-muted`, по центру.

**Крайние случаи.**

| Ситуация | Поведение |
|---|---|
| Игрок в топ-20 | Блок соседей и разрыв не рендерятся вообще. Его строка подсвечена внутри общего списка. |
| Игрок на 21 месте | Разрыв не рендерится (нет пропуска), блок соседей идёт сразу за списком. |
| Игрок на 1 месте | Строки `N−1` нет, показываем `1, 2`. Подсказка меняется на `You are #1 — 440 points ahead of Alex Rivera`. |
| Игрок на последнем месте | Строки `N+1` нет, показываем две строки. |
| Игрок вне рейтинга (0 пиков) | Блок соседей заменяется на строку `Make your first pick to enter the leaderboard`. |

**Фиксированная плашка внизу** остаётся как есть: логика `is-row-visible` (`js/rankings.js:135-152`) просто теперь ориентируется на строку игрока внутри нового блока — селектор `[data-current-rank]` не меняется, менять код не нужно.

**То же правило применяем к списку участников лиги** (`js/league.js:267-304`, сейчас разворачивается полный список из 40): по кнопке `All participants` показываем топ-20 + разрыв + вашу тройку. Это единая механика, разный код держать не нужно — вынести генерацию «топ-N + соседи» в общую функцию.

**Файлы.** `js/rankings.js` (генерация списка 110-113, `scoreFor` 39-47 — теперь нужна разница очков между соседними местами больше 0, иначе подсказка «3 points to pass» будет бессмысленной: у мест 47-64 сейчас у всех по 2 очка → переписать шкалу так, чтобы очки монотонно убывали), `js/league.js`, `css/rankings.css` (+`.rankings-gap`, `.rankings-neighbours`), `css/league.css`.

**Критерии приёмки.**
- В списке ровно 20 позиций до разрыва (3 на подиуме + 17 строк).
- Скролл лидерборда стал короче примерно в 5 раз.
- Блок соседей показывает три реальные позиции вокруг игрока с разными очками.
- Подсказка о разнице очков соответствует числам в строках.
- Все четыре крайних случая из таблицы отрабатывают.

## 10. Фиксированная математика пиков

**Что сейчас.** Очки считаются от вероятностей по модели Пуассона с коэффициентами: `js/data.js:96-127`. `UNIT = { outcome: 50, score: 15, btts: 25 }`, `SCORE_CAP = 900`, очки за точный счёт = `odds(scoreProb(...)) * 15`. Из-за этого счёт `4–1` даёт кратно больше очков, чем `1–1`, — ровно то, что нужно убрать.

**Что делаем.** Полностью фиксированная таблица, без вероятностей и коэффициентов:

| Что выбрал игрок | Очки за карточку |
|---|---|
| Точный счёт | **+30** |
| Только исход (1 / X / 2), без счёта | **+10** |
| Ничего из этого | **0** |
| Максимум за матч | **+30** |
| Максимум за тур (10 матчей) | **+300** |

**Правила начисления:**
1. **Карточка платит один раз — ничего не складывается.**
2. Точный счёт уже содержит в себе исход, поэтому он **заменяет** +10, а не добавляется к нему. Счёт `2–1` = `+30`, а не `+40`.
3. «Обе забьют» очков не приносит. Это остаётся входом на карточке, но в сумму не идёт.
4. Счёт `1–1` и счёт `4–1` дают **одинаковые +30**. Никаких модификаторов за «крупность» счёта, за фаворита/аутсайдера, за коэффициент — ничего.

**Изменения в `js/data.js`:**
- удалить `UNIT` (97) и `SCORE_CAP` (98);
- переписать `pickPoints()` (111-127) на плоские константы `var POINTS = { outcome: 10, score: 30, liveWindow: 20 }` и ветвление «счёт → 30, иначе исход → 10, иначе 0»;
- `odds()`, `outcomeOdds()`, `bttsOdds()` больше не участвуют в подсчёте очков. Из экспорта (`js/data.js:216-227`) `outcomeOdds`/`bttsOdds` убрать — вне `data.js` они не используются (проверено);
- `probs()`, `grid()`, `crowd()` **оставить** — на них держится процент толпы, который показывается после Accept (`js/main.js:328`). Это отображение, а не начисление.

**Изменения в UI (числа из старой шкалы больше не бьются с новой):**
- `index.html:1189` — `Estimated win:` → **`Points at stake:`** (слово «win» тянет за собой ставочную семантику, которой в фиксированной системе нет);
- `index.html:757` — `+150` → `+30`;
- `index.html:768` — `+40` → `+10`;
- блок Scoring в правилах лиги (§5.1) показывает `+10 / +30` — числа берутся из `POINTS`, не дублируются в вёрстке руками;
- очки live-окна (§7.2) — отдельная константа `POINTS.liveWindow = 20`. Это отдельный рынок внутри матча, к сумме карточки он не относится.

**Критерии приёмки.**
- Пик `1–1` и пик `4–1` в разных матчах дают одинаковый `total` = `30`.
- Карточка с точным счётом даёт ровно `+30`, а не `+40` и не `+50`.
- Карточка только с исходом даёт `+10`, и в матче фаворита столько же, сколько в матче равных команд.
- Добавление «Обе забьют» не меняет сумму ни на одной карточке.
- Полный слип из 10 матчей с точным счётом показывает в пикбаре ровно `+300`.
- В коде не осталось ни одного места, где очки умножаются на коэффициент или складываются между рынками.
