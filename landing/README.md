# THE90 — Landing (desktop)

Вёрстка по макету Figma → THE90 → страница `Landing Page` → фрейм **LANDING**
(`1057:11827`, 1440×3988).

```bash
cd /Users/jackmilka/Desktop/THE90 && node .claude/serve.mjs
```

Открыть `http://localhost:4173/landing/`.

## Структура

```
landing/
  index.html            разметка, тексты через data-i18n
  css/landing.css       токены + все секции
  js/i18n.js            словари EN / RU
  js/landing.js         интерактив
  assets/
    icons/              logo, globe, caret, ball, apple, playstore, …
    img/                hero-bg, hero-phones, step-1..3, stadium, pitch, phone-*
    clubs/              крести для карусели и карточки матча
```

Секции сверху вниз: Header → Hero → Clubs → How it works → Features →
Live / Leagues → FAQ + CTA → Footer.

## Интерактив и анимации

| Элемент | Поведение |
|---|---|
| Шапка | sticky, при скролле появляется блюр и граница |
| Навигация | подчёркивание «выезжает» слева направо + свечение |
| Переключатель языка | выпадающий список EN / RU, выбор в `localStorage` |
| Кнопки | подъём, зелёное свечение, блик пробегает по primary |
| Герой | построчное появление, параллакс-наклон мокапа за курсором |
| Чип «Exact score» | появление + бесконечное покачивание |
| Счётчики | 128 000 / 2.4M / 12 досчитывают при попадании в экран |
| Карусель клубов | бесконечная лента, пауза при наведении, ч/б → цвет |
| Карточки шагов | появление снизу, подъём и поворот иллюстрации при наведении |
| **Карточка матча** | рабочая: выбор исхода, счёт ±, счёт сам выбирает исход |
| FAQ | аккордеон с плавной высотой, одновременно открыт один пункт |
| Свечения | `drift` + `hue` — пятна плавно дрейфуют, меняют размер и оттенок |

Всё уважает `prefers-reduced-motion`.

## Соответствие макету

Координаты, размеры, цвета и типографика сняты из `get_design_context` по
каждой секции. Два отступления, сделанных осознанно:

- **Карточка матча** в Figma лежит слоями с масштабом 0.744 (дробные размеры).
  Собрана заново чистой вёрсткой в тех же пропорциях — иначе её нельзя было бы
  сделать интерактивной.
- **Вордмарк Google Play** в экспорте перевёрнут (в Figma он обёрнут в
  `-scale-y-100`), поэтому в CSS к нему применён `transform: scaleY(-1)`.

## Ограничения

- Фоновые изображения full-bleed: тянутся на всю ширину вьюпорта, контент при
  этом остаётся на сетке 1440 по центру.
- Секция `section/scoring` (`1062:13385`) лежит на странице **рядом** с фреймом
  LANDING и в него не входит, поэтому не свёрстана. Пункт «Scoring» в меню ведёт
  на блок со сторами. Скажите, если её нужно добавить.
- Ссылки меню и футера — якоря/заглушки, бэкенда нет.

## Адаптив

Десктопные правила описывают фрейм 1440 как есть; ниже в файле идёт блок
`RESPONSIVE`, который разворачивает абсолютное позиционирование в поток.

| Диапазон | Что меняется |
|---|---|
| `≥1440px` | макет из Figma без изменений |
| `768–1439px` | меню уезжает в бургер, герой и live-блок становятся колонкой, карточки features в 2 ряда |
| `≤767px` | всё в одну колонку, кнопки на всю ширину, CTA из шапки переезжает в меню |

- Бургер-меню: закрывается по клику на ссылку, по клику вне, по `Escape` и при
  переходе обратно на десктоп.
- Параллакс-наклон мокапов включается только при `(hover: hover) and
  (pointer: fine)` — на тач-устройствах он не нужен и инлайновый `transform`
  сбрасывается при смене диапазона.
